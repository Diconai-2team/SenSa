## 5. AI 선행 탐지 리드타임

> threshold 알람 발생 직전 가장 가까운 AI 알람까지의 시간 (500건 샘플)

| 구간 | 건수 | 비율 |
|---|---|---|
| 0~1분 | 500건 | 100.0% |
| 1~5분 | 0건 | 0.0% |

- **평균 리드타임: 0.1분 (약 6초)**
- **중앙값: 0.1분**

> ⚠️ **리드타임 0.1분은 구조적 특성입니다.**
>
> 현재 시스템에서 AI 알람과 threshold 알람이 **거의 동시에** 발생합니다.
> 이유: AI 파이프라인(`run_ai_pipeline_task`)과 임계치 판정(`classify_gas`)이
> **같은 POST 요청에서 트리거**되어 Celery 큐잉 후 수초 내 처리됨.
>
> - **ARIMA/CUSUM 예측 계열**은 이론상 수분~수십분 선행 가능하나,
>   현재 시뮬레이션 환경(1초 주기 spike)에서는 급격한 상승이 많아 리드타임이 짧음
> - **실운영(느린 가스 누출, 드리프트)** 시 CUSUM과 ARIMA의 리드타임이 유의미하게 증가할 것으로 예상

## 8. AI 파이프라인 구성

```
센서 데이터 수신 (POST /dashboard/api/sensor-data/)
       │
       ├─ classify_gas (임계치 판정)     → sensor_caution / sensor_danger (즉시)
       │
       └─ run_ai_pipeline_task.delay()   → Celery AI 워커 (비동기)
              │
              ├── Z-score              → ai_anomaly_warning  (σ 기반 통계 이상)
              │     threshold: 3σ, MIN_WIN: 30샘플
              │
              ├── ChangePoint          → ai_trend_shift       (급격한 평균 이동)
              │     MEAN_SHIFT_THRESHOLD: 2.5
              │
              ├── Isolation Forest     → ai_ml_anomaly        (ML 비선형 이상)
              │     n_estimators=100, contamination=3%, MIN_TRAIN=30
              │     ↳ 배경 스레드 fit (predict만 hot path)
              │
              ├── ARIMA(1,1,1)         → ai_predictive_*      (미래 초과 예측)
              │     FORECAST_STEPS=10, MIN_POINTS=30, REFIT_EVERY_N=주기
              │     ↳ AIPrediction DB 저장 + 검증(expires_at)
              │
              ├── CUSUM                → ai_drift_alert       (완만한 누적 드리프트)
              │     K=0.5σ, H=4.0σ, STALE_TTL=30분
              │
              └── 상관관계 분석        → ai_correlation       (전력↔가스 동시 이상)
```

> **설계 포인트**
> - AI 파이프라인은 Django와 분리된 **Celery 워커(별도 프로세스)** 에서 실행
>   → POST 경로 GIL 점유 없음, Django 포화 방지
> - concurrency=1 → **인메모리 모델 상태 race 없음** (IF/ARIMA/CUSUM 단일 워커 직렬 처리)
> - 슬라이딩 윈도우는 **Redis 기반** (DB 부하 없음, 재시작 시 cold-start 필요)

## 12. 주의 사항

> **현재 수치는 시뮬레이션 데이터 기준입니다.**
>
> 1. 시뮬레이션 환경은 1초 주기 데이터·규칙적 spike 패턴으로 실제 현장보다
>    이상 발생이 잦고 패턴이 명확 → **Precision이 실제보다 높게** 측정될 수 있음
> 2. `arima_cycle`이 sensor_02 CO를 60초마다 자동 ON/OFF → AI 발화 수와
>    ARIMA 예측 수가 편향됨
> 3. 리드타임 평균 0.1분(6초)은 시뮬레이션 급격한 spike 특성 → 실운영의 완만한
>    누출 환경에서는 **CUSUM/ARIMA 리드타임이 수분~수십분으로 증가** 예상
> 4. **실현장 배치 후 1~2주 운영 데이터**로 재측정한 수치를 베이스라인으로 삼을 것
