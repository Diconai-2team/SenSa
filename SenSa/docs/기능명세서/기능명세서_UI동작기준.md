## 1. 계정/인증

### 1-1. 로그인 (`/accounts/login/`)

| # | UI 요소 | 동작 |
|---|---------|------|
| 1 | 아이디 입력란 | 4~20자 텍스트 입력. 이전 실패 시 아이디 자동 채워짐 |
| 2 | 비밀번호 입력란 | 마스킹 텍스트 입력 |
| 3 | **로그인** 버튼 | 아이디/비밀번호 서버 인증 → 성공 시 대시보드 이동, 실패 시 오류 메시지 표시 |
| 4 | **회원가입** 버튼 | 회원가입 페이지(`/accounts/signup/`)로 이동 |
| 5 | 데모 계정 힌트 박스 | `admin / admin1234`, `operator / operator1234` 표시 (개발 환경) |

**표시 조건**
- 로그인 실패 시: 상단에 오류 메시지 표시
- `?next=` 파라미터 있으면 로그인 후 해당 경로로 리다이렉트

---

### 1-2. 회원가입 (`/accounts/signup/`)

| 8 | **로그인 페이지로** 링크 | — | 로그인 페이지 이동 |

### 3-2. 지도 툴바

| # | UI 요소 | 동작 |
|---|---------|------|
| 1 | "📍 실시간 모니터링" 텍스트 | 표시 전용 |
| 2 | `#coord-display` | 마우스 커서의 지도 좌표 실시간 표시 (`x: 123, y: 456`) |
| 3 | **✏️ 지오펜스 그리기** 버튼 | 그리기 모드 진입. 하단에 안내 문구 "클릭으로 꼭짓점 추가 → 첫 점 재클릭으로 완성 (최소 3개)" 표시 |
| 4 | **↩ 취소** 버튼 | 그리기 중인 폴리곤 초기화, 그리기 모드 종료 |

## 4. 대시보드 — 이벤트 현황 (Section 10)

### 4-1. 탭

| # | 탭 | 배치 조건 | 동작 |
|---|---|----------|------|
| 1 | **🔴 위험** | `alarm_level`이 `danger` 또는 `critical`이고 **AI 알람이 아닌 것** | 클릭 → 해당 목록 표시. `#tab-count-danger` 배지에 건수 |
| 2 | **⚠️ 주의** | `alarm_level`이 `caution`이고 **AI 알람이 아닌 것** | 클릭 → 해당 목록 표시. `#tab-count-caution` 배지에 건수 |
| 3 | **🤖 AI탐지** | `alarm_type === 'ai_anomaly'` **또는** 메시지에 `[이상탐지]`·`[ARIMA]` 포함 | 클릭 → AI 이상탐지 알람 목록 표시. `#tab-count-ai` 배지에 건수 |

**탭 배치 판정 순서 (resolveTab):** AI 여부를 가장 먼저 확인한다. AI 알람이면 레벨에 무관하게 AI탐지 탭에 들어간다. AI가 아닌 것만 레벨로 위험/주의를 구분한다.

탭 전환 시 비활성 패널은 `display:none`. 활성 탭 하단 색상 강조(위험=빨강, 주의=노랑, AI탐지=보라 `#a78bfa`).

### 4-2. 알람 목록

| # | UI 요소 | 동작 |
|---|---------|------|
| 1 | **+ 상세보기** 링크 | `/dashboard/alarms/` 새 탭 열기 |
| 2 | 알람 아이템 클릭 | 해당 알람 읽음 처리 (`PATCH /dashboard/api/alarm/{id}/read/`) → `unread` 스타일 제거 |
| 3 | `#alarm-badge` | 미읽음 전체 건수. 0이면 숨김 |

| 5 | 실시간 수신 (경로 1) | WebSocket `alarm.new` 도착 시 → `resolveTab()`으로 탭 결정 후 맨 위에 삽입. `alarm_level !== 'info'`이면 배너도 표시 |
| 6 | 실시간 수신 (경로 2) | WebSocket `anomalyDetected` 이벤트 도착 시 → `alarm_type: 'ai_anomaly'`로 강제 설정 후 AI탐지 탭에 삽입. DB 저장 여부와 무관하게 즉시 표시됨 |
| 7 | 페이지 로드 시 | `/dashboard/api/alarm/` 에서 최근 50개 불러와 탭별 분류 |

> **경로 1 vs 경로 2 차이:** 경로 1은 `Alarm` DB에 저장된 알람이 WebSocket으로 전달됨 (alarm_id 있음). 경로 2는 IF 탐지 결과가 DB 저장 전에 직접 WebSocket으로 전달될 수 있어 alarm_id가 `null`일 수 있다.

## 27. AI 이상탐지 시스템 — 동작 흐름

> 운영자가 AI탐지 탭 알람을 이해하기 위한 참고 정보. 직접 조작하는 UI는 없고, 자동으로 탐지 및 표시됨.

### 27-1. 탐지 방식 2종

| 방식 | 탐지 축 | 원리 | 알람 메시지 접두사 |
|------|--------|------|-----------------|
| Isolation Forest (IF) | 공간축 — 여러 센서 조합 | 여러 측정값의 패턴이 평소 분포와 다를 때 이상 판정 | `[이상탐지]` |
| ARIMA | 시간축 — 단일 센서 추세 | 과거 시계열로 미래를 예측해 실측과의 괴리 또는 임계치 진입 예상 시 경보 | `[ARIMA]` |

단일 센서가 임계치를 초과하는 경우(기존 방식)와 달리, AI 탐지는 **임계치를 넘지 않아도** 경보를 발행할 수 있다.

---

### 27-2. IF 탐지 발동 조건

- 센서 데이터 수신 누적 **30개 이상**부터 작동 (이전엔 판정 건너뜀)
- 탐지 이상 점수가 기준 미만(CONTAMINATION 5% 이상치 기준)이면 알람 생성
- 20번 수신마다 모델 자동 재학습

---

### 27-3. AI 알람 생성 → 화면 표시 전체 흐름

```
센서 데이터 수신 (POST /devices/sensor-data/)
  │
  ├─ 기존 임계치 판정 (classify_gas / classify_power)
  │
  └─ detect_anomaly() — IF 이상 판정
       │
       ├─ 정상 또는 샘플 부족 → 종료 (알람 없음)
       │
       └─ 이상 감지 → Alarm DB 저장 (alarm_type='ai_anomaly')
                        └─ publish_alarm() → Redis Channel Layer
                             └─ WebSocket → 브라우저
                                  └─ SenSa.on('alarm') — 경로 1
                                       └─ resolveTab() → 'ai' 탭 삽입
```

또한 WebSocket에서 `anomalyDetected` 이벤트가 직접 오는 경우(경로 2):
```
SenSa.on('anomalyDetected') → alarm_type='ai_anomaly' 강제 부여 → 'ai' 탭 삽입
```

### 27-4. AI탭 알람 아이템 표시 형식

| 필드 | 내용 |

### 27-5. AI 예측 성능 패널과의 연계 (Section 16)

AI 예측 성능 패널(`#section-16`)은 `AIPrediction` 모델 기록을 기반으로 동작한다.

| UI 요소 | 연결 데이터 |
|---------|-----------|
| 성공 TP | 예측 후 실제로 임계치 초과가 발생한 건수 (`result='success'`) |
| 오경보 FP | 예측했지만 임계치 미도달 (`result='failure'`) |
| 미탐지 FN | 임계치 초과가 발생했지만 예측이 없었던 건수 |
| 검증 중 | 아직 결과 판정이 안 된 건수 (`result='pending'`) |
| 최근 예측 목록 | 장치ID, 가스키, 예측값, 결과배지 — 최근 5건 |
