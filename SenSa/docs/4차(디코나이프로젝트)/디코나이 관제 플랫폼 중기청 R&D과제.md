### 프로젝트 개요

본 프로젝트는 산업 현장에서 발생할 수 있는 유해가스, 전력 이상, 작업자 위치 위험 등 다양한 안전 요소를 실시간으로 수집·분석·시각화하고, 이를 기반으로 위험 상황을 사전에 감지하고 대응할 수 있는 통합 관제 플랫폼을 구축하는 것을 목표로 한다.

센서 및 IoT 네트워크를 통해 수집되는 데이터를 기반으로  
운영자가 한 화면에서 현장 상태를 직관적으로 파악할 수 있도록 대시보드를 구성하며,  
지오펜스(위험 구역), 이벤트 관리, 작업자 위치 정보 등을 통합하여 운영자 중심의 관제 시스템을 구현한다.

또한, 단순 모니터링을 넘어 AI 기반 시계열 분석(ARIMA 등)을 적용하여 이상 징후를 사전에 탐지하고, 임계치 초과 또는 위험 패턴 발생 시 자동 알림을 제공하는 지능형 안전관리 시스템으로 확장한다.

이는 산업 현장의 안전관리 패러다임을  
사후 대응에서 사전 예측 및 예방 중심으로 전환하는 것을 핵심 방향으로 한다.

---
### 제작 전략
```
1단계 = 보여주는 것 (UI + 데이터 흐름)  
2단계 = 살아있는 시스템 (AI + 모니터링 + 운영)
```

| 구분   | 3차 프로젝트 | 4차 프로젝트      |
| ---- | ------- | ------------ |
| 목적   | UI + 흐름 | 운영 + 확장      |
| 데이터  | 가짜      | 실제 구조        |
| AI   | 없음      | 있음           |
| 모니터링 | 없음      | 있음           |
| 인프라  | 로컬      | Docker + K8s |
| 난이도  | 낮음      | 높음           |
```
3차 프로젝트: 보이게 만들어라
4차 프로젝트: 제대로 돌아가게 만들어라
```

### 프로젝트 목적 

✔️ 핵심 목적
본 프로젝트의 궁극적인 목적은  
센서 기반 실시간 데이터와 AI 분석을 결합하여 산업 현장의 위험을 사전에 감지하고,  
운영자가 즉시 대응할 수 있는 통합 관제 플랫폼을 구축하는 것이다.

✔️ 세부 목적
1. 실시간 안전 데이터 통합 관리
- 유해가스 센서 및 전력 시스템 데이터를 실시간으로 수집
- 센서(Device), 이벤트(Event), 위치 정보 등을 통합 관리  
    👉 (센서 데이터 구조 및 수집 체계 기반)

2. 직관적인 관제 대시보드 구축
- 지도 기반 UI를 통한 현장 시각화
- 센서 상태, 위험도, 이벤트를 한 화면에서 확인  
    👉 (통합 대시보드 요구사항 명시)

3. 위험 구역(지오펜스) 기반 안전 관리
- 특정 공간을 위험 구역으로 정의
- 작업자 위치와 센서 데이터를 결합하여 위험 판단
- 위험 구역 진입 시 경고 및 알림 제공

4. 임계치 기반 위험 감지
- 가스 농도 및 전력 데이터 기준 임계치 적용
- 정상 / 주의 / 위험 단계 자동 분류  
    👉 (임계치 정의 기준 존재)

5. AI 기반 이상 탐지 및 예측
- 시계열 데이터 기반 이상 패턴 분석
- ARIMA 등 모델을 활용한 미래 위험 예측  
    👉 (AI 기반 분석 및 예측 시스템 요구사항)

6. 실시간 알림 및 대응 체계 구축
- 위험 발생 시 즉시 알람 제공
- 이벤트 기록 및 이력 관리
- 관리자 대응 프로세스 지원

7. 운영 환경 적용 가능한 MVP 구축
- 실제 서비스 가능한 형태의 초기 시스템 구현
- Docker 및 클라우드 기반 배포 환경 구성  
    👉 (MVP 구축 목표 명확)


✔️ 한 줄 핵심 정의
```
이 프로젝트는
센서 + 위치 + AI를 결합하여 산업 현장의 위험을 실시간으로 감지하고 예측하는 
지능형 관제 시스템 구축
```

```

```

### 영역별 기술 스택

🔵 엣지 게이트웨이 (센서 데이터 수집)

역할

- 스트리밍 전달

기술 스택
- FastAPI
- uvicorn

적용 이유

- WebSocket 지원이 간단하여 스트리밍 구현 용이
- 경량 구조로 엣지 환경에 적합

- 권한 관리
- 지오펜스 / 이벤트 처리

기술 스택

- Django REST Framework (DRF)
- Django ORM

적용 이유

🔵 지도 및 지오펜스

기술 스택
- Leaflet.js (가볍고 추천)  

역할
- 공장 평면도 기반 지도 구현
- 센서 위치 시각화
- 지오펜스(위험 구역) 설정 및 표시

참고)
지오펜스 실제 생성위치
```
Django (Template)
   ↓
HTML + JS (Leaflet)
   ↓
DRF API (JSON)
```

지오펜스 처리 방식 (핵심 로직)
지오펜스는 별도의 통신을 통해 동작하는 것이 아니라, 센서 데이터가 유입될 때마다 서버에서 비교하여 판단한다.

동작 흐름
```
① 지오펜스 생성 (1회)  
   브라우저 → DRF → DB 저장  
  
② 센서 데이터 지속 입력  
   센서 → 서버  
  
③ 서버 판단  
   "현재 위치가 지오펜스 내부인가?"  
  
④ 조건 만족 시  
   → 알람 발생
```

핵심 개념
- Leaflet: 지도 UI (프론트엔드)
- DRF: 데이터 저장 및 처리 (백엔드)

전체 흐름
```
① 공장 이미지 업로드  
② 좌표 시스템 생성  
③ 지오펜스 설정  
④ 센서 위치 배치  
⑤ 작업자 위치 이동 (시뮬레이션)  
⑥ 센서 데이터 수신  
⑦ 서버 판단 (지오펜스 + 임계치)  
⑧ 알람 발생
```

🔵 모니터링 (Prometheus / Grafana)

역할
- 시스템 상태 수집
- 성능 분석
- 장애 탐지 및 대응


기술 스택
- Prometheus
- Grafana
- (옵션) Alertmanager


적용 대상
✔ Django (관제 서버)
- API 요청 수
- 응답 시간
- 에러율
- 지오펜스 판단 시간
- 알람 발생 횟수
👉 django-prometheus 사용


✔ FastAPI (센서 / AI 서버)
- WebSocket 연결 수
- 센서 데이터 처리 속도
- AI 분석 시간
- 에러율
👉 prometheus-fastapi-instrumentator 사용


✔ Celery
- 작업 처리 시간
- 큐 적체 상태
- 실패율


✔ Redis / DB
- 연결 상태
- 처리량
- 응답 지연


적용 구조
```
FastAPI / Django / Celery  
        ↓  
    Prometheus (수집)  
        ↓  
    Grafana (시각화)
```

적용 시점
- 1단계 (MVP): 선택 적용
- 2단계 (AI/실시간): 필수 적용
